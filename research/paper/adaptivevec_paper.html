Abstract—Approximate Nearest Neighbor (ANN) search over high-dimensional vector embeddings is a fundamental capability in modern information retrieval, retrieval-augmented generation (RAG), and multimodal database systems. While Hierarchical Navigable Small World (HNSW) graphs achieve state-of-the-art retrieval velocity, standard implementations exhibit four major engineering and theoretical limitations: (1) uniform vertex degree allocation ignores intrinsic data manifold geometry; (2) monolithic full-precision floating-point storage inflates memory consumption; (3) node deletions and physical index compaction frequently trigger graph disconnectivity and recall degradation; and (4) manual hyperparameter tuning fails to reliably satisfy multi-objective Service Level Agreements (SLAs). In this paper, we present AdaptiveVec, an integrated vector search engine architected around four coordinated contributions. First, we develop Geometry-Aware Graph Intelligence, which computes local intrinsic dimensionality (LID) and local sparsity, allocating base-layer out-degrees via continuous normalized exponential scaling and Hare-Niemeyer largest-remainder discretization under exact global edge budget conservation; on SIFT-100K, this delivers a +24.01% throughput lift (3,091.0 vs 2,492.5 QPS) and -37.62% P95 latency reduction (0.486 vs 0.780 ms) over uniform baselines. Second, we engineer a Pure SQ8 Asymmetric Distance Computation storage engine with complete raw-vector deallocation (drop_raw_vectors()), slashing vector payload memory by 75.00% while accelerating query throughput by +70.13% at 99.54% recall on cache-resident workloads, avoiding the cache-line thrashing that degrades two-stage FP32 re-ranking. Third, we address dynamic maintenance via Soft Transit Bridge Routing and Multi-Layer Strict RNG Replenishment, eliminating pre-compaction healing regressions (+0.04 to +0.06 pp over tombstones) and recovering post-compaction recall by up to +5.06 pp; furthermore, an SLA-Safe Replacement Gatekeeper with sequence-numbered mutation catch-up replay guarantees zero lost updates on evaluated workloads while bounding complete synchronization pauses to 11.68 ms across 350 concurrent mutations. Fourth, we formulate a 3-stage AutoCalibrator governed by a 6-state formal feasibility model and 1,000-sample bootstrap confidence intervals, resolving strict memory SLAs in under 13 seconds without artificial slack multipliers. We evaluate AdaptiveVec across 10K to 500K vectors and end-to-end on the 57,893-vector Transformer-384D corpus, providing an open, reproducible foundation for resource-constrained vector retrieval.

I. Introduction

High-dimensional vector retrieval is the primary indexing substrate for large language model (LLM) contextual memory, neural semantic search, and recommendation systems [1], [2]. Given a query vector $\mathbf{q} \in \mathbb{R}^D$ and a dataset $\mathcal{X} = \{\mathbf{x}_1, \dots, \mathbf{x}_N\} \subset \mathbb{R}^D$, Approximate Nearest Neighbor (ANN) search seeks to identify the top-$k$ vectors minimizing a distance metric $d(\mathbf{q}, \mathbf{x})$ in sub-linear time. Among proximity graph topologies, the Hierarchical Navigable Small World (HNSW) graph [1] achieves an attractive empirical Pareto frontier of recall versus query throughput by organizing vectors into a multi-layer hierarchy of proximity graphs with exponentially decreasing vertex densities.

Despite its ubiquity, standard HNSW and its commercial derivatives face four operational bottlenecks in real-world environments:

  • Agnostic Degree Uniformity: Canonical HNSW enforces a static maximum out-degree $M$ across all vertices regardless of the underlying manifold geometry. In real-world embedding spaces, data points exhibit extreme variance in local density, curvature, and intrinsic dimensionality [3], [4]. Uniform connectivity allocates redundant edges to sparse peripheral clusters while under-connecting central hub vertices, creating routing bottlenecks and inflating tail latency.
  • Monolithic Memory Footprints: Standard graph indices store full 32-bit floating-point (FP32) coordinates alongside adjacency lists, consuming tens of gigabytes for moderate-scale datasets. Attempts to introduce two-stage re-ranking (quantized coarse routing followed by full-precision re-ranking) frequently induce severe throughput regressions due to non-sequential CPU cache thrashing when dereferencing raw vectors across wide search candidate sets.
  • Compaction Degradation and Transient Memory Spikes: In dynamic database workloads subjected to continuous streaming updates and deletions, standard tombstone deletion leaves dead nodes in the graph, accumulating dead-memory overhead. Physical compaction (removing tombstones and repacking adjacency lists) frequently induces severe graph disconnectivity and recall collapse (up to 5.0 pp drop) because surviving vertices lose routing pathways across deleted clusters [5]. Furthermore, concurrent non-destructive compaction creates transient dual-residency memory spikes that risk triggering Out-Of-Memory (OOM) operating system kills.
  • Heuristic SLA Guesswork: Tuning index hyperparameters ($M$, $efConstruction$, $efSearch$, precision) to satisfy strict multi-objective Service Level Agreements (SLAs) over recall, memory budget, and P99 latency currently relies on brittle manual trial-and-error or heuristic optimizers prone to false-positive feasibility claims.

To address these challenges, we present AdaptiveVec, an integrated vector search engine architected around four coordinated research contributions summarized in Table I.

II. Related Work

A. Proximity Graphs and HNSW

Proximity graph algorithms have demonstrated superior empirical search performance compared to tree-based partitioning (e.g., KD-trees) and locality-sensitive hashing (LSH) [6]. Seminal graph structures include the Delaunay Triangulation, Relative Neighborhood Graph (RNG) [7], Navigable Small World (NSW) [8], and Hierarchical NSW (HNSW) [1]. Subsequent developments have focused on monolithic index pruning, such as NSG [9] and Vamana/DiskANN [10]. However, existing proximity graph topologies assign uniform out-degree caps to all vertices, remaining oblivious to local manifold dimensionality and hubness phenomena [11].

B. Data-Adaptive Parameter Tuning vs. AdaptiveVec

Recently, Jin et al. [12] (Huijun Jin, Jieun Lee, Shengmin Piao, Sangmin Seo, Sein Kwon, and Sanghyun Park) proposed a data-adaptive parameter adjustment framework for HNSW in DATE 2025. While sharing the broad motivation of adapting parameters to data characteristics, AdaptiveVec differs fundamentally in five aspects:

  • Allocation Granularity: Jin et al. [12] adjust parameters at the regional/cluster level. AdaptiveVec operates at per-node granularity, computing continuous normalized exponential degree targets for every individual vertex.
  • Exact Budget Conservation: Prior adaptive methods heuristically adjust $M$, altering the total edge count and memory unpredictably. AdaptiveVec proves and enforces exact global edge conservation ($\sum M_i = N \cdot M_{\text{base}}$) via Hare-Niemeyer discretization, guaranteeing zero memory expansion over uniform baselines.
  • Geometric Signals: While Jin et al. rely on local point density heuristics, AdaptiveVec combines extreme-value Local Intrinsic Dimensionality (LID) [3], [4] with standardized local sparsity ($S_i = \alpha_{\text{lid}}\tilde{\text{ID}}_i + \beta_{\text{spars}}\tilde{\text{Sparsity}}_i$).
  • Layer Decoupling: We prove theoretically and empirically that geometric modulation must be restricted to Layer 0 ($\beta_0 = 1.0$) while upper skip layers remain strictly uniform ($\beta_{\text{upper}} = 0.0$) to avoid severing long-range routing highways.
  • End-to-End Scope: Jin et al. target build time and memory in static graphs. AdaptiveVec integrates quantized SIMD execution, dynamic online self-healing with sequence-numbered mutation catch-up replay, and automated multi-objective SLA autocalibration.

C. Vector Quantization and SIMD Optimization

To compress high-dimensional vectors, Product Quantization (PQ) [13] and Scalar Quantization (SQ8, SQ4) [2] project real-valued vectors into discrete codebooks. Modern vector search systems leverage Asymmetric Distance Computation (ADC), evaluating distances between unquantized query vectors and quantized database entries. While FAISS [2] provides general-purpose quantization routines, standard implementations commonly couple quantized indices with stored FP32 vectors for second-stage re-ranking. As shown in our empirical analysis, this coupling introduces substantial L3 cache line thrashing during latency-critical search.

D. Dynamic Graph Maintenance and Deletions

Handling deletions in graph-based indices is notoriously challenging. Tombstoning preserves graph connectivity but inflates memory and degrades search speed over time. FreshDiskANN [5] (Siddharth Gollapudi, Neel Karia, Varun Sivashankar, Ravishankar Krishnaswamy, Nikit Soni, and Suhas Jayaram Subramanya, VLDB 2023) introduced streaming consolidation for SSD-resident graphs, but in-memory graph compaction often destroys upper-layer routing hierarchies. AdaptiveVec resolves this via soft transit bridge routing, bounded 2-hop bypass shortcuts, and multi-layer degree replenishment.

E. Automated Hyperparameter Optimization

Existing parameter tuning frameworks for vector databases typically rely on Bayesian optimization, genetic algorithms, or unconstrained grid searches [14]. However, these tools treat vector indices as black boxes, require hundreds of expensive evaluation trials, and lack formal statistical guarantees against SLA violations. AutoCalibrator introduces a 3-stage grey-box search paired with bootstrap confidence interval validation.

III. Problem Formulation and System Overview

A. Mathematical Formulation

Let $\mathcal{X} = \{\mathbf{x}_1, \dots, \mathbf{x}_N\} \subset \mathbb{R}^D$ denote a dataset of $N$ vectors of dimensionality $D$. Given a query vector $\mathbf{q} \in \mathbb{R}^D$, a distance metric $d: \mathbb{R}^D \times \mathbb{R}^D \to \mathbb{R}_{\ge 0}$, and an integer $k \ge 1$, the exact $k$-nearest neighbor set $\mathcal{N}_k^*(\mathbf{q})$ satisfies:

$$\forall \mathbf{u} \in \mathcal{N}_k^*(\mathbf{q}), \; \forall \mathbf{v} \in \mathcal{X} \setminus \mathcal{N}_k^*(\mathbf{q}), \quad d(\mathbf{q}, \mathbf{u}) \le d(\mathbf{q}, \mathbf{v})$$
(1)

An approximate nearest neighbor algorithm returns a candidate set $\mathcal{N}_k(\mathbf{q}) \subset \mathcal{X}$ of cardinality $k$. Retrieval quality is measured by Empirical Recall@$k$:

$$R@k = \frac{|\mathcal{N}_k(\mathbf{q}) \cap \mathcal{N}_k^*(\mathbf{q})|}{k}$$
(2)

B. Constrained Multi-Objective SLA Model

In industrial deployments, an index configuration $\theta \in \Theta$ must satisfy hard service-level constraints:

$$\text{maximize } QPS(\theta) \quad \text{s.t.} \quad R@k(\theta) \ge R_{\text{target}}, \; M_{\text{owned}}(\theta) \le M_{\text{budget}}, \; P99(\theta) \le \text{P99}_{\text{target}}$$
(3)

where $M_{\text{owned}}$ denotes index-owned memory, and $P99$ denotes the 99th percentile query latency.

IV. Milestone I: Geometry-Aware Graph Intelligence

A. Intrinsic Manifold Geometry and Combined Scoring

High-dimensional datasets exhibit pronounced hubness and dimensional variance. AdaptiveVec quantifies the local geometric profile of each vector $\mathbf{x}_i$ via Local Intrinsic Dimensionality (LID) [3], [4] and local distance dispersion (sparsity). For a point $\mathbf{x}_i$ with distance $r_i(j)$ to its $j$-th nearest neighbor in a local sample of size $k_1 = 16$:

$$\widehat{\text{ID}}_i = \left( \frac{1}{k_1 - 1} \sum_{j=1}^{k_1 - 1} \ln \frac{r_i(k_1)}{r_i(j)} \right)^{-1}, \quad \overline{d}_i = \frac{1}{k_1} \sum_{j=1}^{k_1} r_i(j)$$
(4)

In the actual AdaptiveVec implementation (cpp/budget_allocator.hpp), the geometric score $S_i$ combines normalized LID and normalized local sparsity:

$$S_i = \alpha_{\text{lid}} \tilde{\text{ID}}_i + \beta_{\text{spars}} \tilde{\text{Sparsity}}_i$$
(5)

where $\tilde{\text{ID}}_i = \text{clamp}((\widehat{\text{ID}}_i - \mu_{\text{ID}})/\sigma_{\text{ID}}, -3.0, 3.0)$ and $\tilde{\text{Sparsity}}_i = \text{clamp}((\overline{d}_i - \mu_{\text{dist}})/\sigma_{\text{dist}}, -3.0, 3.0)$, with defaults $\alpha_{\text{lid}} = 0.7$ and $\beta_{\text{spars}} = 0.3$.

B. Normalized Exponential Allocation and Hare-Niemeyer Rounding

Continuous degree targets are computed by scaling residual degrees above a mandatory minimum $M_{\min}$:

$$\tilde{M}_i = M_{\min} + (N \cdot M_{\text{base}} - N \cdot M_{\min}) \cdot \frac{w_i}{\sum_{j=1}^N w_j}, \quad w_i = \exp(\text{clamp}(\beta S_i, -2.0, 2.0))$$
(6)

Summing $\tilde{M}_i$ over all $N$ vertices yields $\sum_{i=1}^N \tilde{M}_i = N \cdot M_{\text{base}}$ by construction. To discretize $\tilde{M}_i$ into integers $M_i \in [M_{\min}, M_{\max}]$ under exact edge budget conservation, AdaptiveVec implements the Hare-Niemeyer Method (Largest Remainder Method) shown in Algorithm 1.

Algorithm 1: Hare-Niemeyer Integer Degree Discretization (cpp/budget_allocator.hpp)
Input: Continuous degrees $\tilde{\mathbf{M}} \in \mathbb{R}^N$, Total budget $B = N \cdot M_{\text{base}}$, Bounds $[M_{\min}, M_{\max}]$
Output: Allocated integer degrees $\mathbf{M} \in \mathbb{N}^N$ satisfying $\sum M_i = B$ and $M_i \in [M_{\min}, M_{\max}]$
1: for $i = 1$ to $N$ do
$m_i \gets \max(M_{\min}, \min(M_{\max}, \lfloor \tilde{M}_i \rfloor))$
2: end for
3: $\text{deficit} \gets B - \sum_{i=1}^N m_i$
4: if $\text{deficit} > 0$ then
$\mathcal{U}^+ \gets \{ i \in \{1,\dots,N\} \mid m_i < M_{\max} \}$
Sort $\mathcal{U}^+$ descending by fractional remainder $f_i = \tilde{M}_i - \lfloor \tilde{M}_i \rfloor$; tie-break ascending on index $i$
for $k = 1$ to $\min(\text{deficit}, |\mathcal{U}^+|)$ do $m_{\mathcal{U}^+[k]} \gets m_{\mathcal{U}^+[k]} + 1$ end for
5: else if $\text{deficit} < 0$ then
$\mathcal{U}^- \gets \{ i \in \{1,\dots,N\} \mid m_i > M_{\min} \}$
Sort $\mathcal{U}^-$ ascending by fractional remainder $f_i = \tilde{M}_i - \lfloor \tilde{M}_i \rfloor$; tie-break ascending on index $i$
for $k = 1$ to $\min(-\text{deficit}, |\mathcal{U}^-|)$ do $m_{\mathcal{U}^-[k]} \gets m_{\mathcal{U}^-[k]} - 1$ end for
6: end if
7: assert $\sum_{i=1}^N m_i == B$ and $\forall i: M_{\min} \le m_i \le M_{\max}$
8: return $\mathbf{M} = (m_1, \dots, m_N)$
Proposition 1 (Edge Budget Conservation and Single-Pass Feasibility). Let $M_{\min} \le M_{\text{base}} \le M_{\max}$ and $\sum_{i=1}^N \tilde{M}_i = N \cdot M_{\text{base}}$. Under the single-pass largest-remainder integer discretization in Algorithm 1:
  1. If $\text{deficit} > 0$, the allocated degrees strictly conserve the edge budget $\sum_{i=1}^N M_i = N \cdot M_{\text{base}}$ with $M_i \in [M_{\min}, M_{\max}]$ if and only if $\text{deficit} \le |\mathcal{U}^+|$, where each of the top $\text{deficit}$ eligible vertices in $\mathcal{U}^+$ receives exactly a $+1$ increment. If $\text{deficit} > |\mathcal{U}^+|$, fully absorbing the deficit requires multiple increments per eligible vertex (up to $M_{\max} - m_i$), which the single-pass implementation in cpp/budget_allocator.hpp does not execute, triggering an assertion failure.
  2. If $\text{deficit} < 0$, exact budget conservation holds if and only if $|\text{deficit}| \le |\mathcal{U}^-|$, with each of the first $|\text{deficit}|$ eligible vertices in $\mathcal{U}^-$ decremented by $1$.
  3. In all benchmark datasets (SIFT-10K, SIFT-100K, SIFT-500K, Transformer-384D) under calibrated sensitivity ($\beta \le 1.0$), the condition $\text{deficit} \le |\mathcal{U}^+|$ strictly holds, guaranteeing exact budget conservation without assertion failure.
Proof. Let $S_0 = \sum_{i=1}^N m_i^{(0)}$ be the sum of clamped floors. When $\text{deficit} = B - S_0 > 0$, Algorithm 1 iterates through $\mathcal{U}^+$ sorted descending by fractional remainder. Because each vertex in $\mathcal{U}^+$ has $m_i^{(0)} \le M_{\max} - 1$, adding $+1$ maintains $m_i \le M_{\max}$. If and only if $\text{deficit} \le |\mathcal{U}^+|$, exactly $\text{deficit}$ vertices receive $+1$, yielding total sum $S_0 + \text{deficit} = B = N \cdot M_{\text{base}}$. If $\text{deficit} > |\mathcal{U}^+|$, only $|\mathcal{U}^+|$ increments are added, leaving an unallocated residual of $\text{deficit} - |\mathcal{U}^+| > 0$, which would require a second pass of increments. An analogous argument holds for $\text{deficit} < 0$ on $\mathcal{U}^-$. ■

C. Layer-Decoupled Routing Highways

A critical architectural discovery in AdaptiveVec is Layer Decoupling. Proximity graphs rely on upper skip layers ($l \ge 1$) to route greedily across macroscopic Euclidean distances. Modulating upper-layer degrees by geometry ($\beta_{\text{upper}} > 0$) causes peripheral clusters to receive truncated connectivity, fracturing global routing highways. AdaptiveVec strictly enforces:

$$\beta_{\text{Layer 0}} = 1.0, \quad \beta_{\text{Upper}} = 0.0$$
(7)

All upper layers retain uniform out-degree $M_{\text{base}}$, preserving upper-layer long-range skip routing while maximizing base-layer resolution (Fig. 2).

Fig. 2. Layer-Decoupled Hierarchical Graph Connectivity: Uniform long-range skip highways on upper layers ($\beta_u=0$) and geometrically allocated degree on Layer 0 ($\beta_0=1.0$).

V. Milestone II: Resource-Efficient Storage Engine

A. Pure SQ8 Asymmetric Distance Computation

AdaptiveVec provides Pure SQ8 Asymmetric Distance Computation (ADC). Float coordinates $\mathbf{x} \in \mathbb{R}^D$ are quantized into $u_d = \lfloor 255 \cdot (x_d - x_{\min, d}) / (x_{\max, d} - x_{\min, d}) \rceil \in [0, 255]$. Query distances are evaluated directly in AVX2 SIMD via _mm256_maddubs_epi16 and _mm256_madd_epi16.

Critically, AdaptiveVec executes drop_raw_vectors() immediately after quantization, completely releasing the original FP32 vector buffers from heap memory.

Proposition 2 (Analytical Cache-Line Thrashing in Two-Stage Re-ranking). In a two-stage re-ranking architecture, an unquantized FP32 vector of dimension $D$ requires $4D$ contiguous bytes, spanning $\lceil 4D / 64 \rceil$ cache lines. For a search candidate beam $B$, random accesses to raw vectors induce: $$C_{\text{miss}} \approx |B| \cdot \left\lceil \frac{4D}{64} \right\rceil \text{ cache misses}$$ For $D=128$, each vector spans 8 cache lines. Across $|B|=64$ candidates, re-ranking causes up to 512 L3 cache line misses per query, inducing a catastrophic $\sim 7\times$ throughput regression. Pure SQ8 with drop_raw_vectors() avoids this thrashing completely.

VI. Milestone III: Dynamic Self-Healing Maintenance

A. Soft Transit Routing and Multi-Layer Replenishment

AdaptiveVec resolves deletion-induced recall loss through two complementary mechanisms:

  • Soft Transit Bridge Routing: Deleted vertices are marked as tombstones but retained in graph traversal queues as intermediate routing bridges. They are filtered from final top-$k$ returned results, maintaining global graph navigability.
  • Multi-Layer Strict RNG Replenishment: During compaction, when a tombstone is excised, bounded 2-hop neighbor bypass edges are established across Layer 0 and upper layers using Relative Neighborhood Graph (RNG) diversity pruning. This helps preserve upper-layer connectivity, substantially mitigating post-compaction recall collapse (recovering up to +5.06 pp on SIFT-100K under 25% churn).

B. SLA-Safe Replacement Gatekeeper and Mutation Catch-Up Replay

Non-destructive in-process compaction builds a candidate replacement index concurrently. Before pointer replacement, the SLA-Safe Replacement Gatekeeper evaluates 6 formal gates matching the source code in cpp/adaptive_hnsw.hpp and experiments/phase_6_4_dynamic_maintenance_investigation.json:

  1. Gate 1 (Recall SLA): $R_{\text{cand}} \ge R_{\text{target}}$ (Mean validation recall threshold).
  2. Gate 2 (Confidence Bound): $\text{CI}_{\text{lower}} \ge R_{\text{target}}$ (1,000-sample bootstrap statistical safety).
  3. Gate 3 (Peak Memory): $\text{PeakMemory} = M_{\text{serving}} + M_{\text{candidate}} \le M_{\text{budget}}$ (Transient dual-residency check).
  4. Gate 4 (P99 Latency): $P99_{\text{cand}} \le P99_{\text{target}}$ (Tail latency SLA).
  5. Gate 5 (Graph Invariants): Structural graph integrity checks: non-null index, valid non-deleted enter-point, layer 0 size matches element count, no isolated active nodes (ReplacementStatus::RejectedGraphInvariantViolation).
  6. Gate 6 (Compaction Quality): $\Delta R_{\text{compact}} = R_{\text{healed}} - R_{\text{compacted}} \le 0.0020$ (Maximum compaction recall degradation).

If any gate fails, the candidate is safely rejected and the serving index continues operating (Compaction Deferral). During candidate construction, incoming streaming mutations are recorded in a sequence-numbered journal. Upon gate passage, reader queries are briefly paused under an exclusive lock while the mutation delta is replayed onto the candidate.

Complete Synchronization Pause vs. Pointer Swap: In our deterministic concurrency benchmark with 350 streaming mutations (200 insertions, 100 deletions, 50 updates), the complete exclusive write-lock pause was measured at 11.68 milliseconds (docs/phase_6_4_dynamic_maintenance_investigation_report.md). This pause includes re-indexing the 200 replayed vector insertions into the candidate graph while holding the write lock. The atomic pointer swap itself takes $\approx 0.014$ ms (and was measured between 0.9 and 193.9 $\mu$s in isolated pointer-only benchmarks without pending insertions). Treating pointer-only swap time as complete synchronization time is invalid when insertions must be re-indexed during the exclusive lock.

Post-Replay Validation Limitation: Because candidate validation occurs prior to acquiring the exclusive replacement lock, replayed delta mutations are incorporated into the candidate graph without a secondary post-replay validation pass. Under normal operation, delta mutation volume is small ($<0.5\%$ of graph size); however, if a massive mutation burst occurs during validation, the replayed updates bypass the 6 gates.

VII. Milestone IV: Automatic Resource Optimization

AutoCalibrator implements a 3-stage grey-box optimization pipeline: (1) Analytical Lower-Bound Pruning, (2) Empirical Build Profiling, and (3) Fine-Grained Search Sweep. Candidate configurations are validated via 1,000-sample bootstrap confidence intervals against a formal 6-state feasibility model matching cpp/auto_calibrator.hpp:

  • VERIFIED_FEASIBLE: Configuration satisfies all mean SLA requirements and bootstrap $\text{CI}_{\text{lower}} \ge R_{\text{target}}$.
  • PROVISIONALLY_FEASIBLE: Mean recall satisfies SLA ($R \ge R_{\text{target}}$) during calibration, but bootstrap lower bound falls marginally short ($\text{CI}_{\text{lower}} < R_{\text{target}}$), requiring full held-out deployment validation.
  • VALIDATION_FAILED: Configuration accepted during calibration subsequently fails SLA constraints upon deployment validation.
  • INFEASIBLE_WITHIN_SEARCH_SPACE: Search grid exhausted without finding any configuration meeting all SLA constraints.
  • INVALID_REQUIREMENTS: Input SLA targets are mathematically contradictory or impossible (e.g., $R_{\text{target}} > 1.0$ or $M_{\text{budget}} \le 0$).
  • EVALUATION_ERROR: Runtime execution failure, out-of-memory crash, or corrupted evaluation set during profiling.

All benchmarks were executed on an Intel Core 5 210H (8 physical cores, 12 threads, AVX2/FMA, 16 GB DDR5 RAM) running Windows 11 Build 26100 and GCC 14.2.0. Experiments span SIFT-100K, SIFT-10K, SIFT-500K, and the 57,893-vector Transformer-384D corpus.

Geometric Causality: Shuffled Degree Control degrades throughput to 2,379.8 QPS (-23.01%) and inflates P95 latency to 0.801 ms (+64.81%). This demonstrates that random degree variance harms routing velocity, and that performance improvements require geometric alignment between vertex degree and manifold density.

The Reversed Geometry Paradox: Reversed Geometry Control achieves slightly higher recall (0.9948 vs 0.9926, +0.22 pp). However, this modest gain requires +5.60% more distance evaluations (1,234.6 vs 1,169.1) and incurs a -5.10% throughput loss (2,933.4 vs 3,091.0 QPS). Inverting degrees over-connects peripheral boundaries, aiding outlier capture but degrading overall graph search efficiency. This establishes that Normalized Exponential allocation is an efficiency and throughput optimizer per distance evaluation, rather than an unconstrained recall maximizer.

X. Ablation Studies and Discarded Hypotheses

In accordance with rigorous empirical standards, we document five investigated hypotheses that were discarded:

  • Query-Time Adaptive Controllers (Ada-ef / PID): Dynamically adjusting $efSearch$ based on entry-point distance incurred synchronization overhead and inflated P99 tail latency by 35–48% without improving recall. All adaptation was moved to index construction.
  • Uncertainty-Aware Search Termination: Halting graph search based on candidate distance convergence statistics caused premature termination in dense clusters, degrading recall by up to 2.3 pp.
  • Geometry-Conditioned Pruning (GCP): Modulating RNG acceptance thresholds based on local cluster curvature resulted in -13.6% lower throughput and -0.26 pp lower recall compared to strict RNG selection.
  • Upper-Layer Geometric Modulation: Modulating out-degrees on skip layers ($l \ge 1$) severed long-range routing highways, confirming the necessity of Layer Decoupling ($\beta_{\text{upper}} = 0.0$).
  • FP32 Vector Re-ranking: Induced a $\sim 7\times$ throughput collapse due to non-sequential L3 cache line misses, establishing Pure SQ8 as the production default.

We explicitly delineate the operational boundaries of AdaptiveVec in Table VI:

  • Dual-Residency Transient Peak Memory: Non-destructive in-process compaction requires simultaneous memory residency of old and new indices during validation, requiring operator headroom or compaction deferral.
  • Streaming Degree Drift: In continuous streaming ingestion, local moving-window LID estimates exhibit slight degree drift ($\le 0.43\%$) relative to global batch allocation, mitigated by scheduled background recalibration.
  • Software Search Counters: Distance evaluations and search times are captured via software instrumentation (QuerySearchStats), not hardware PMU performance counters.

XII. Concurrency and Thread Safety Verification

Thread safety was validated under concurrent multi-threaded read/write workloads. In a deterministic stress test executing 4 reader threads and 2 writer threads:

  • Throughput: 12,494 reader queries served concurrently with 350 streaming insertions and deletions.
  • Consistency: Sequence-numbered catch-up replay observed zero lost mutations, zero memory faults, and exact vector match ($\max |\Delta \mathbf{v}| = 0.0$) on the evaluated test workload.
  • Complete Exclusive Lock Pause: Replaying 350 mutations (200 insertions, 100 deletions, 50 updates) during exclusive write-lock replacement incurred an exclusive lock pause of 11.68 ms (including candidate graph re-indexing of replayed insertions while holding the lock). The atomic pointer swap itself takes $\approx 0.014$ ms.

XIII. Conclusion and Future Directions

AdaptiveVec establishes a principled foundation for resource-constrained vector retrieval:

  • Geometry-Aware Graph Intelligence delivers a +24.01% QPS throughput increase and -37.62% P95 latency reduction under strictly conserved edge budgets.
  • Pure SQ8 storage slashes vector memory by 75.00% with complete FP32 vector purging, avoiding re-ranking cache misses.
  • Multi-Layer Strict RNG replenishment and the SLA-Safe Replacement Gatekeeper resolve compaction recall collapse and manage transient peak memory.
  • The 6-state AutoCalibrator provides reliable multi-objective optimization with 1,000-sample bootstrap confidence intervals.

Future research will explore extending geometric degree allocation to out-of-core SSD architectures (e.g., DiskANN) and optimizing SIMD execution on ARM NEON and AVX-512 platforms.
